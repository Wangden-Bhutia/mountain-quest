# Mountain Quest

A seventeen-chapter HTML5 canvas platformer with a training ground. It is written in vanilla JS, makes no external requests, runs on phones by touch, and can be installed as an app that plays offline.

Play: https://wangden-bhutia.github.io/mountain-quest/

## Story
1. **The Empty Bell.** The village bell's clapper broke in an autumn storm, and the wind carried the pieces up the mountain. Grandmother Amu sends her granddaughter to bring them home. She goes through the meadow (Ch 1), the Lake of Echoes (Ch 2) and Whispering Pines, where she finds the first shard (Ch 3), then the Ice Steps (Ch 4).
2. **Rising stakes.** At the Summit (Ch 5) there is only a second shard and huge hoofprints: something took the last piece. She follows them across the Crumbling Ridge (Ch 6), the Windy Pass (Ch 7), Frozen Falls (Ch 8) and Starlit Gorge (Ch 9). The trail goes on over Moonlit Moraine (Ch 10), where the tracks vanish among the boulders; Glacier Slide (Ch 11), where a tuft of grey fur proves Old Horn came this way; Spring Canyon (Ch 12); the Gusting Bridges (Ch 13); and the Frost Gate (Ch 14). Then comes Storm Peak (Ch 15), as the storm closes in.
3. **Climax.** In Old Horn's Hollow (Ch 16), Old Horn, the grandfather of all grumps, hoards shiny things. Three bounces on his head change his mind, and he gives up the last piece.
4. **Ending.** In The Long Way Down (Ch 17), she races the storm home with a tailwind. She rings the bell, the yaks come home, and up on the mountain Old Horn hums along.

## Run and test
```
npm ci
npm test               # data checks, physics unit tests, a solvability check for every stage
./serve.sh &           # serves at http://127.0.0.1:8765/mountain-quest/
npx playwright install chromium
npm run test:e2e       # mobile smoke tests, axe, overlap, save/load, input, screenshots
npm run solve          # prints the solver's finishing time for each stage
```
`tests/solver.js` runs a beam search over the real `js/physics.js` at 120 Hz, using left, right and jump inputs in 0.1 s steps. A stage only passes if it can be finished **without losing a life**. A control test checks that an impossible stage is rejected.

## Install and offline
- `manifest.webmanifest` and the icons in `icons/` (a bell and mountain made for the app; the photo is not used) let Chrome on Android offer "Install app". The button appears in the title menu and in Settings only after the browser fires `beforeinstallprompt`. It is hidden once the game is installed. On iPhone and iPad it shows how to use Add to Home Screen.
- `sw.js` caches every game file (cache first, same origin only) so the game works with no connection. It is generated by `node tools/build-sw.js`, which builds the version from the file hashes. Run it after changing any game file. CI fails if `sw.js` is stale.
- When a new version is deployed, it installs in the background and shows a quiet "Update ready" note.
- Save data is now v2. A v1 (12-chapter) save is migrated: chapters after Starlit Gorge move up by five, so the old Chapter 11 (Old Horn) is now Chapter 16.

## Files
- `index.html` and `css/style.css`: the page, HTML menus and touch controls. A strict CSP allows no external origins.
- `js/shell.js`: full screen, manual landscape and the sound button.
- `js/physics.js`: the world model and fixed-step physics, with no DOM, so node tests can use it.
- `js/data.js`: stages and story text.
- `js/game.js`: rendering, audio, input, menus and saving.
- `js/assets.js`: the original sprites.
- `original.html`: the untouched original, kept for reference (not deployed).
- `docs/audit.md`: the audit of the original.

The GitHub Actions workflow runs every test, then deploys only `index.html`, `css/` and `js/` to Pages.
